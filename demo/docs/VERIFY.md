# VERIFY.md — 上电验证 SOP（智能盲杖 Demo v1）

> 阶段 5 产出物。配套固件：`demo/HAL_SMART_STICK`（`UV4 -b` 编译 0 Error / 0 Warning，Flash 47.8 KB / RAM 4.8 KB）。
> **用法：从上往下按单执行，每步都写明了「做什么 / 看到什么算通过 / 不通时先查什么」。**
> 任何一步卡住，把该步的命令输出 + `status` / `err` 两行结果发我即可远程定位。
>
> 串口参数：**115200 8N1**，接 PA9(TX)→USB-TTL 的 RX、PA10(RX)→USB-TTL 的 TX、GND 共地。
> 建议终端开**本地回显关闭**（我们的 shell 会回显你输入的字符）。

## 0. 前置检查（不通电，先看线）

| # | 检查项 | 正确做法 | 常见错误 |
|---|---|---|---|
| 0.1 | L298N **ENA/ENB 跳线帽** | **必须拆掉**（否则 PWM 调速无效，电机永远全速） | 忘拆 → `motor 300` 也是全速 |
| 0.2 | L298N **5V 跳线帽** | **拆掉**，5V 脚由降压模块供电（12.6V 满电时留着会烧 78M05） | 留着 → 稳压器发烫、逻辑电压漂 |
| 0.3 | L298N 逻辑电 | 降压模块 5V → L298N 的 5V 脚 | 没接 → 电机完全不动 |
| 0.4 | IN1~IN4 下拉 | 各 10kΩ 到 GND（防复位期间乱动） | 没接 → 上电瞬间轮子抖一下 |
| 0.5 | ENA/ENB 下拉 | 各 10kΩ 到 GND | 同上 |
| 0.6 | 电机消噪 | 每个电机端子并 100nF；电源入口并 100µF | 没加 → MCU 莫名复位 |
| 0.7 | HC-SR04 供电 | **5V**（不是 3.3V），模块旁并 100nF | 接 3.3V → 测距不稳/无回波 |
| 0.8 | HC-SR04 ECHO 分压 | ECHO →[2.2kΩ]→ PA1，PA1 →[3.3kΩ]→ GND | ⚠️ 不分压 → 打坏 PA1 |
| 0.9 | I²C 上拉 | 模块自带即可，**不要再加**；若通信不稳只留一组 | 多组并联 → 总线拉不下来 |
| 0.10 | 共地 | 电池负极 / 降压模块 / MCU / 所有模块 / L298N 全部共地（星形） | 没共地 → 各种玄学 |
| 0.11 | 电池 | 11.1V/1200mAh（3S）**仅台架测试**；带保护板 | — |

**接线核对**（照着 `PINOUT.md` 2.2 节的端口表逐根对）：`PA0=TRIG / PA1=ECHO / PA4=分压中点 / PA9-PA10=串口 / PA11-PA12=按键 / PB0-PB1=ENA/ENB / PB6-PB7=I2C / PB8=振动 / PB9=蜂鸣器 / PB12-PB15=IN1-IN4`。

## 1. 最小上电（只接 ST-Link + USB-TTL，外设一个都不接）

**做法**：烧录后按复位（或 `Reset and Run`），打开串口。

**通过标准**：

1. 串口出现 banner：
   ```
   =====================================
    SmartStick - smart cane demo v0.1.0
    build ... 
    SYSCLK 72MHz | I2C1 400k | PWM 18k
    type 'help' for commands
   =====================================
   ```
2. **PC13 蓝色 LED 以 1Hz 闪烁**（不依赖串口的"活着"证据）
3. 出现 `[E][US  ] ...` 或 `[W][APP ] US pins NOT configured` 之类的告警是**正常的**（此时没接外设）
4. `help` 能列出全部命令；`ver` / `status` 有输出

**不通时先查**：串口 TX/RX 是否交叉、波特率是否 115200、是否共地、是否真的烧进去了（`ver` 的 build 时间）。

---

## 2. I²C 总线（挂 OLED + MPU6050 + QMC5883L 后）

```
i2c
```
**通过标准**：列出 `0x0D`(QMC5883L) / `0x3C`(OLED) / `0x68`(MPU6050)，且**没有** "missing" 提示。

**不通时**：① 模块是否供电（OLED/MPU/QMC 都接 3.3V，先试 3.3V）；② PB6/PB7 是否接反；③ 上拉是否被并联太多（把某模块的上拉电阻拆掉只留一组）；④ 降速验证：`cfg` 不能改 I²C 速率（CubeMX 里），可临时把模块逐个拔掉定位。

---

## 3. OLED

```
oled stat        → present=1
oled test        → 屏上出现 4 行测试文本
```
**通过标准**：4 行文字清晰、不左右错位（若整体错位 2 列 → 实物是 SH1106，告诉我，我把 `drv_oled.c` 的 `OLED_COL_OFFSET` 改 2）。
上电时也应先看到开机屏，随后进入实时仪表盘（S/D/T/V/U/I/E 四项）。

---

## 4. 按键

```
key mon 20       → 按着 SOS 键时看到 SOS=DOWN，松开变 up
```
**通过标准**：按住/松开能实时反映；`key` 能看到 short/long/vlong 计数增加（长按 1s 松手 → long+1）。

## 5. 报警执行器

```
buzz 500         → 蜂鸣器响 0.5s
vib 500          → 振动马达振 0.5s
alarm fall       → 循环长鸣+振动（SOS 模式）
alarm off        → 立刻停
alarm mute 1     → 静音；alarm mute 0 → 恢复
```
**通过标准**：声音、振动都正常；`alarm fall` 会一直循环直到 `alarm off`。

**不通时**：蜂鸣器不响 → 你的模块可能是**高电平触发**：改 `cfg.h` 的 `CFG_BUZZER_ACTIVE_LOW` 为 0 重新编译（或告诉我）。振动马达不转 → 查 S8050 基极 1kΩ、续流二极管方向、马达是否接 5V/3.3V。

## 6. 电池电压（需要万用表）

```
batt
```
**通过标准**：读数与万用表实测 **相差 < 3%**。

**标定方法**（差值大时）：
1. 万用表量电池正负极 → 记 `V_actual`（例如 11.85V）
2. 读 `batt` → 记 `V_read`（例如 11.20V）
3. `cfg set batt_div_ratio_x1e4 <新值>`，新值 = 43000 × V_actual / V_read ≈ 45400
4. 再读 `batt` 复核

**阈值**：默认低电 10.5V / 严重 9.9V（3S）。换正式电源后按 `PINOUT.md` 4.4 节改。

## 7. 超声波 HC-SR04（**核心功能**）

```
us               → 读一次（mm）
us mon 10        → 每 150ms 打一次，共 10 次
```
**通过标准**：
1. 拿尺子量正前方障碍物，读数与**实际距离相差 < ±3cm**（20cm~2m 范围内）
2. 移开障碍物（>4m 或朝天花板）→ 读数饱和到 4000mm 或 `invalid`
3. 手掌贴住模块（<2cm）→ 显示 `invalid`（过近，属正常）
4. 连续测 20 次，`err` 里的 `US` 计数**不应持续增长**（偶发 +1 正常）

**不通时**：① 5V 供电是否到位（实测模块 VCC 电压）；② ECHO 分压是否接对（PA1 空闲电压应 ≈0V）；③ TRIG 是否接 PA0；④ `status` 里 `us pins` 是否为 `configured`（若是 `NOT configured` → CubeMX 那步没生效，告诉我）。

## 8. 姿态 MPU6050

```
imu mon 10
```
**通过标准**：
1. 静置时 `|a| ≈ 1000mg`（±60mg 内）
2. 杖身**竖直** → `tilt` ≈ 0~10%
3. 杖身**放平**（横躺） → `tilt` ≈ 95~100%
4. 快速晃动 → `gyro` 数值明显变化

## 9. 磁力计 QMC5883L（P2）

```
mag              → 看三轴数值
mag cal start    → 手持原地缓慢转 360°（3~5 秒）
mag cal stop     → 打印偏移与范围
```
**通过标准**：旋转过程中三轴数值明显变化；`cal done` 后 range 合理（X/Y 通常 >200）。
**注意**：**远离电机与电源线**做校准；磁力计 v1 不做航向业务，只要求"能读、能校准"。

## 11. 电机（⚠️ **先让轮子离地**！）

```
motor stop                → 确认不动
motor 300 300             → 两轮同向慢速转（约 75ms 后到速）
motor 300 -300            → 原地转向（换向保护：先停 60ms 再反向）
motor brake               → 立即刹停（比 stop 更硬）
motor stop                → 滑行停
```
**通过标准**：
1. 方向正确：`motor 300 300` 时**两轮都朝"人推车前进"的方向**；若某个轮反了 → `cfg set motor_l_invert 1`（或 r）即可，**不用拆线**
2. 速度可调：`motor 200 200` 明显比 `motor 700 700` 慢（说明 ENA/ENB 跳线帽确实拆了）
3. 无异响、L298N 不烫（超过 60℃ 就停一会）

**不通时**：① 电机电源 12V 是否到位；② L298N GND 是否与 MCU 共地；③ 5V 逻辑电是否接；④ 单个轮子测 `motor 300 0` 定位是哪一路。

## 12. 牵引联调（手扶杆推行，**人在旁边随时准备接管**）

```
guide start      → 状态变 GUIDE，OLED 左上角显示 GUIDE
guide status     → 看 avoid 等级与 scale
```
**通过标准**：
1. 前方开阔 → 前进，速度 = `guide_base_duty`(600) × scale
2. 走近障碍（1.2m 内）→ **减速** + 每 700ms 短鸣
3. 再近（0.4m 内）→ **停车** + 双短鸣 + 振动（持续）
4. 后退一点（>0.6m，回滞）→ 重新前进
5. 全程串口无 `err` 激增

**偏航标定**（直行跑偏时）：
- 偏左 → `cfg set motor_trim_l <+20>`；偏右 → `cfg set motor_trim_r <+20>`，每次 20，逐步补

**按键联动**：SOS 短按 = 开始/停止牵引；MODE 短按 = 静音开关（OLED 第 3 行显示 MUTE）。

## 13. ★绕行调参（可选，先做完 12 再做）

| 步骤 | 命令 | 看什么 |
|---|---|---|
| 1 | `guide spin L 700 400` | 转向速度是否合适（太慢 → duty 加；太快 → 减） |
| 2 | `guide spin R 700 400` | 两个方向都试 |
| 3 | `cfg set detour_spin_ms 700` | 一次转向的量够不够（转不够 → 加） |
| 4 | `cfg set detour_fwd_ms 900` | 试探前进的距离合不合适 |
| 5 | `cfg set detour_recheck_mm 600` | 认为"通了"的门限（应 > `avoid_stop_mm`+`avoid_hyst_mm`） |
| 6 | `guide detour 1` | 打开绕行，`guide status` 看 `detour=spin/probe`、`attempts` |

**通过标准**：遇障停车 2s 后自动转向、试探、若通即继续前进；连续 3 次不通则停车并提示。
**调好后**：`cfg list` 把参数抄进本文档末尾的标定记录表。

## 14. 跌倒检测（**在软垫/床上做，别摔坏**）

1. 先 `imu mon 10` 确认姿态指标正常（竖直 tilt≈0%）
2. 手持杖身竖直，**让它自然侧倒到软垫上**（模拟跌倒）
3. 预期：**长鸣 800ms×3 + 同步振动（循环）**，OLED 显示 `S:SOS`，`guide` 停止
4. 清除：按住 SOS 键 3 秒（或 `alarm clear`）→ 回到 IDLE

**误报/漏报调参**：

| 现象 | 调整 |
|---|---|
| 正常晃动就报警 | `cfg set fall_impact_mg 3000`（提高冲击门限）或 `cfg set fall_tilt_deg10 650` |
| 倒地了但不报 | `cfg set fall_tilt_deg10 450`（降低姿态门限）、`cfg set fall_confirm_ms 1200` |
| 太灵敏/太迟钝 | 优先调 `fall_impact_mg` 与 `fall_tilt_deg10` |

## 15. 长稳测试（10 分钟）

- 保持 `guide start` 或 `imu mon 0` 空跑，观察：`err` 计数是否增长、`tasks` 里有无任务 max 耗时异常（>10ms 就要查）、L298N 与电机温度、MCU 是否复位（复位会重打 banner）。

## 附 B：已知局限（先说清楚，避免误判为 bug）

1. **跌倒检测是启发式**：剧烈晃动可能误报、缓慢躺倒可能漏报；v1 目标是"能演示、可调参"。
2. **超声波对软质/斜面反射差**（布料、草丛、斜墙）→ 会显示 invalid；此时系统按"有障碍"处理（fail-safe）。
3. **参数掉电丢失**（v1 不写 Flash）：`cfg save` 返回 UNSUPPORTED 是预期行为；重启回到默认值。
4. **绕行是"试探式"**：单路前向传感器看不到两侧，绕行可能来回试；装上第二路超声波后可升级为选边转向。
5. **蓝牙 v1 只有骨架**：无手机协议，只有回显/收发测试。
6. **L298N 有约 2V 压降**：12.6V 满电时电机实际约 10.6V，转速略低于标称，属正常。
